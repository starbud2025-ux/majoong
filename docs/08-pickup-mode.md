# 08. 등·하원 픽업 모드 (메인 기능) 설계 초안

> 기존 F2(창문·도어)·F3(뒷좌석 알림)는 차량 자체 기능과 겹치므로 **보조(마무리 확인)** 로 내리고, 아이 승하차 한 번의 흐름을 돕는 이 모드를 메인으로 한다.

## 문제
학교·학원 앞 짧은 정차에서 학부모는 급하게 아이를 태우고 내리게 한다. 가방·벨트·뒷문 쪽 안전·정차 시간 압박 때문에 확인을 놓친다.

## 흐름 (정차 전용, 기어 P에서만)
1. 운전자가 홈에서 **"픽업 모드"** 를 켠다(수동 시작. 위치 SDK가 Coming Soon이라 자동 인식은 v2).
2. **승차**: 뒷줄 좌석별 탑승 감지 → "뒷좌석 오른쪽에 탑승했어요" / 안전벨트 미착용 좌석 안내 → 모두 착용되면 "출발 준비 완료"(벨트 확인 전까지 출발 안내를 주지 않음)
3. **하차**: 뒷줄 도어 열림 감지 → "인도 쪽 문으로 내리세요"(좌/우 문구는 사용자 설정: 주행 국가·정차 방향) + 동승자용 큰 글씨 안내(짧게)
4. **마무리 확인**: 좌석에 남은 탑승 / 열린 창문·도어(기존 F2) → "모두 내렸어요"
5. 주행 시작(기어≠P) 시 즉시 종료·차단 (기존 정차 전용 규칙)

## 수용 기준 (테스트로 먼저 옮길 것)
- AC5.1 픽업 모드가 꺼져 있으면 아무 안내도 하지 않는다.
- AC5.2 뒷줄 좌석별(좌·중·우) 탑승·벨트 상태를 **개별 판단**한다. 읽지 못하면 "확인 불가"이며 착용으로 간주하지 않는다.
- AC5.3 벨트 미착용 좌석이 하나라도 있으면 "출발 준비 완료"를 표시하지 않는다.
- AC5.4 기어가 P를 벗어나면 즉시 종료하고 상태를 저장하지 않는다.
- AC5.5 아동 정보(이름·사진·나이 등)를 입력받지 않고, 좌석 점유 불리언만 메모리에서 사용한다.
- AC5.6 지원하지 않는 차량(capability 불가)은 일반 문구("뒷좌석을 확인하세요")로 degrade한다.

## 구현 영향
- core: `Seat`에 뒷줄 중앙(`REAR_CENTER`) 추가, `VehicleSignals`에 `seatBelts: Flow<Map<Seat, BeltState>>`, `doors`/`windows` 기존 재사용, `PickupController`(또는 AppState 확장) + `Settings.pickupMode`·`curbSide`
- app: 홈에 "픽업 모드" 버튼, 승차/하차 화면(큰 글씨·고대비 디자인 가이드 유지), 설정에 정차 방향(좌/우)
- fake: 벨트·뒷줄 3좌석 데모 시나리오 추가
- pleos 어댑터: 위 §9 API (조회만 사용)
