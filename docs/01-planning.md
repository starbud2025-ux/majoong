# 01. 기획

## 1. 문제 정의
운전자는 차를 **세우는 순간**과 **떠나기 직전**에 같은 종류의 실수를 반복한다.

| 시점 | 흔한 실수 | 결과 |
|---|---|---|
| 주차할 때 | 주정차 금지 구역인 줄 모르고 세움 | 과태료, 견인 |
| 내릴 때 | 창문 열림, 뒷좌석에 사람·물건 남김, 문 잠금 확인 누락 | 도난, 방치 사고, 불편 |
| 출발할 때 | 앞유리·사이드미러 서리나 김서림을 닦지 않고 출발 | 시야 불량, 위험 |

한 앱이 "내리기 전 → 출발 전" 수명주기 전체를 정차 상태에서 챙긴다.

## 2. 목표
- 정차 중에만 동작하는 단순하고 안전한 앱 (주행 중 조작 없음)
- 한 번의 확인과 한 번의 실행으로 끝나는 UX
- 공개 SDK 범위 안에서 **실제로 동작하는 데모**(에뮬레이터 + Fake 차량)

## 3. 범위

### v1 (공모전 제출)
| ID | 기능 | 핵심 |
|---|---|---|
| F1 | 주정차 구역 경고 | 기어가 P로 바뀌는 순간 현재 위치를 구역 데이터와 대조해 경고 |
| F2 | 하차 전 점검 | 창문, 도어, 경고, 뒷좌석 탑승 상태를 요약해 음성·화면으로 안내 |
| F3 | 뒷좌석 안내 | 뒷좌석 탑승이 감지되면 하차 점검에 "뒷좌석 확인" 항목과 동승자용 안내 화면 |
| F4 | 출발 전 시야 루틴 | 서리·김서림 제거 루틴 제안과 실행(제습·와이퍼·사이드미러 열선·핸들 열선), 결과 보고 |

### 제외 (기획서의 "향후 요청 API"로만 기술)
- 문콕·뺑소니 감지, 주변 차량 영상 공유 (카메라·충격·주변 차량 API 없음)
- 자동 경적, 제한속도 강제 속도 제어 (제어 API 없음, 안전·법적 문제)
- 뒷좌석 전용 오디오 출력 (SDK에 오디오 존 제어가 확인되지 않음)
- 차량 간 직접 무선통신(V2V)

## 4. 차별점과 경쟁 상황
공개 저장소 조사 기준(2026-11-04, 전체 참가작 아님):
- **겹침**: 서리·김서림·시야 복구는 ClearView 등이 이미 구현. **단독 기능으로는 차별성이 없다.**
- **빈 영역(확인한 범위)**: "내릴 때 불법 주정차 경고"와 "하차·출발 수명주기 묶음"은 찾지 못함.
- 따라서 서리 제거는 **독립 기능이 아니라 "출발 전 점검" 단계의 한 부품**으로 위치시키고, 앱의 메시지는 "차를 세우고 떠나는 모든 순간을 챙긴다"로 잡는다.
- 제출 전에 다시 한 번 공개 저장소·공지에서 유사작을 검색한다(docs/06).

## 5. 사용자
- 주 사용자: 출퇴근·장보기 등 짧게 자주 세우는 운전자
- 보조 사용자: 아이·부모를 태우는 가족 운전자(뒷좌석 안내), 겨울철 야외 주차 운전자(서리 루틴)

## 6. 성공 기준 (심사 관점 가정)
1. 에뮬레이터에서 F1~F4 시나리오가 끊김 없이 재현된다.
2. 차량 상태 변화를 **SDK 콜백으로 확인**해서 결과를 보여 준다(버튼만 누르고 끝나지 않음).
3. 정차 전용 정책을 지킨다(주행 중 차단).
4. README만 보고 심사자가 빌드·실행·검증할 수 있다.

|---|---|---|
| 제어 퍼미션 미승인 | F4 제어 불가 | F4를 "안내만" 모드로 degrade, 승인 요청 경로 확인 |
| 뒷좌석 탑승 감지 API 부재 | F3 약화 | 감지 불가 시 "뒷좌석 확인하세요" 일반 안내로 대체 |

| 에뮬레이터 성능(GPU 필요) | 개발 지연 | core 로직과 Fake 차량으로 에뮬레이터 없이 개발·시연 |
