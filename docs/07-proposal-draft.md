# 07. 기획서 초안 v2 (접수양식 02번 "앱 프로젝트 소개 / 심사 자료")

> 상태: **v2.1 — 실제 SDK(Vehicle 2.3.2) 검증 결과 반영, 검토 대기.** 사용자 검토·수정 후 접수양식 DOCX에 옮긴다.
> 작성 규칙(양식): 이름·연락처·이메일·소속·개발자 실명을 쓰지 않는다. 분량 제한 없음.
> `[확인]` = 사용자가 확정할 값. `(가정)` = 근거 자료가 없는 추정. `[진행 예정]` = 아직 안 한 일.
> 정직성 원칙: 구현된 것과 예정인 것을 구분해 쓴다. 차량 제조사의 기존 기능에 대한 단정(없다/있다)은 하지 않는다.

**앱명 / 프로젝트명:** 마중 (팀: 별틔움) — 아이를 마중 나가는 순간을 챙겨 주는 등·하원 픽업 도우미. `[확인: Pleos 프로젝트 이름도 "마중"으로 수정 가능]`

---

## 1. 앱 한 줄 소개
학교·학원 앞 짧은 정차에서 **아이가 타고 내리는 한 번의 흐름**(좌석별 안전벨트 확인 → 인도 쪽 문 안내 → 마무리 점검)을 돕는 **정차 전용** 차량 앱.

## 2. 기획 배경

**주목한 순간: 등·하원 픽업의 "30초".** 학부모는 학교·학원 앞에서 짧게 정차하며 아이를 급히 태우고 내리게 한다. 뒤차와 시간에 쫓기는 이 순간에 확인할 것이 한꺼번에 몰린다.

| 고객이 겪는 불편 | 왜 놓치는가 |
|---|---|
| 아이가 탔는데 **어느 좌석의 벨트가 안 채워졌는지** 모르고 출발한다 | 급하고, 뒤를 돌아볼 수 없고, 아이가 둘 이상이면 더 헷갈린다 |
| 아이가 **차도 쪽 문**을 열고 내린다 | 하차 방향을 말로 매번 알려 주기 어렵다 |
| 다 내렸는지, 뒷좌석·창문·도어는 어떤지 확인하지 않고 떠난다 | 정차 시간이 짧아 마무리를 건너뛴다 |

**왜 차량 앱인가:** 위 판단은 모두 **좌석별 탑승·안전벨트·도어 상태**라는 차량 데이터가 있어야 가능하다. 스마트폰 앱은 어느 좌석에 누가 앉았는지, 벨트가 채워졌는지, 어느 문이 열렸는지 알지 못한다. 또한 이 순간 운전자는 폰을 볼 수 없고 차량 화면과 음성만 쓸 수 있다.

**기존 차량 경고와의 차이:** 차량의 개별 경고(예: 벨트 미착용 경고음)는 "하나의 사건"을 알린다. 이 앱은 **등·하원이라는 상황 하나를 승차→하차→마무리로 이어서** 좌석별로 보여 주고, 정차 방향 설정에 맞춰 "어느 문으로 내릴지"까지 안내한다. `[확인: 제출 전 현대·기아 기존 기능과의 중복 범위를 제조사 공개 자료로 다시 확인]`

## 3. 앱 주요 기능 및 차량 특화 요소

**설계 원칙: 정차 전용.** 기어가 P일 때만 동작하고(Vehicle SDK의 기어 값으로 판별, 읽지 못하면 차단), 주행 중이면 화면 조작과 차량 제어를 즉시 중단한다. Driver Distraction Optimization은 선언하지 않는다. 운전자는 정차 후 버튼 한 번(픽업 모드)만 누르면 된다.

### 3-1. 메인: 등·하원 픽업 모드 (로직·화면 구현 완료, 차량 연결 코드 작성 완료 · 에뮬레이터 검증 `[진행 예정]`)
| 단계 | 하는 일 | 사용하는 차량 정보 |
|---|---|---|
| 승차 | 뒷줄 **좌석(왼쪽·가운데·오른쪽)별** 탑승과 안전벨트를 카드로 표시. 미착용 좌석이 있으면 "뒷좌석 오른쪽 안전벨트를 확인하세요", 탑승자 전원 확인 시 "안전벨트를 모두 확인했어요" | 좌석 탑승, 좌석 벨트 |
| 하차 | 뒷문이 열리면 **정차 방향 설정**(오른쪽/왼쪽)에 따라 "오른쪽 문으로 내리세요". 반대쪽(차도 쪽) 문이면 "차도 쪽 문이에요. 오른쪽 문으로 내려 주세요" | 도어 열림 |
| 동승자 안내 | 하차 때 동승자용 큰 글씨 안내("내릴 때 주변 차와 자전거를 살펴보세요") | - |
| 마무리 | "모두 내렸어요" → 남은 탑승자·열린 창문·도어를 점검해 이상 항목만 요약. 읽지 못한 항목은 "확인 불가"(차량 경고등 정보는 퍼미션 제약으로 조회하지 않아 항상 "확인 불가"로 표시) | 좌석, 창문, 도어 |

**신뢰성 설계 (심사자가 확인할 수 있는 수용 기준 AC5.1~5.6, 자동 테스트로 검증)**
- 읽지 못한 값은 "착용"이 아니라 **"확인 불가"**로 표시한다. 전원 착용이 **확인되기 전에는** "모두 확인했어요"를 말하지 않는다.
- 벨트·탑승 감지를 지원하지 않는 차량은 "직접 확인해 주세요"라는 일반 문구로 낮추고, 준비 완료를 말하지 않는다.
- 기어가 P를 벗어나면 즉시 종료하고 이후 신호로 되살아나지 않는다.
- 같은 안내는 반복해서 말하지 않는다(운전 중이 아니어도 음성 피로 방지).

### 3-2. 보조 기능 (같은 정차 흐름 안에서)
| 기능 | 하는 일 | 상태 |
|---|---|---|
| 주정차 구역 경고 | 기어 P 시 위치를 구역 데이터와 대조해 "주정차 금지 구역일 수 있어요"(단정 금지). 학교 앞 정차 시 의미가 큼 | 구현 완료(가상 샘플 구역 5곳). 위치 SDK(FusedLocation)가 신청 불가라 현재 차량 연결에서는 "위치 확인 불가" 안내 |
| 출발 전 시야 루틴 | 서리·김서림 제거 단계를 **사용자 동의 후** 실행·확인. 제어 불가 시 단계별 안내 모드 | 안내 모드 구현 완료. 제습·와이퍼 1회 제어 코드는 작성했고(실행 후 제습 상태를 다시 읽어 확인) Vehicle Control SDK 개방·에뮬레이터 검증 후 사용. 열선은 단계 값의 의미를 확인하지 못해 안내만 `[진행 예정]` |

### 3-3. 차량 특화 요소 (모바일 대비 우위)
1. **좌석 단위 차량 데이터**(탑승·벨트)로 "누가, 어느 자리에서 무엇을 놓쳤는지"를 짚는다 — 모바일은 알 수 없는 정보.
2. **기어 P 전환·도어 열림**을 트리거로 쓰므로 앱을 조작하는 횟수가 최소다(픽업 모드 켜기 1회).
3. **정차 전용 안전 설계**가 구조의 일부다.
4. 음성은 짧게, 화면은 한눈에 보이게 구성(Pleos UI 디자인 가이드: 대비 4.5:1 이상, 최소 12sp, 터치 햅틱, 주야간 자동 전환). 화면 모션은 정차 중 상태 설명용(전환·진행률·경고 표시)으로만 쓰고, 주행 중에는 화면이 차단되며 반복 모션이 모두 멈춘다(가이드: 운전 중 동영상·애니메이션 이미지·텍스트 자동 스크롤 금지).

## 4. 주요 사용 시나리오

**시나리오 A — 학원 앞 픽업 (메인)**
1. 학부모 A가 학원 앞에 정차해 기어를 P로 놓고 "픽업 모드"를 켠다.
2. 아이 두 명이 뒷좌석 왼쪽·오른쪽에 탄다. 화면이 좌석별로 "왼쪽: 벨트 착용 / 오른쪽: 벨트 미착용"을 보여 주고 "뒷좌석 오른쪽 안전벨트를 확인하세요"라고 말한다.
3. 오른쪽 아이가 벨트를 매면 화면이 바로 바뀌고 "안전벨트를 모두 확인했어요"가 나온다. A는 뒤를 돌아보지 않고 출발할 수 있다.
4. 다음 정차(귀가)에서 아이가 **왼쪽(차도 쪽) 문**을 열면 "차도 쪽 문이에요. 오른쪽 문으로 내려 주세요"가 나온다. 아이가 오른쪽 문으로 내리면 "오른쪽 문으로 내리세요"가 나온다.
5. A가 "모두 내렸어요"를 누르면 남은 탑승자·열린 창문·도어를 확인하고 "모두 정상이에요"로 끝난다.

**시나리오 B — 감지 불가 차량 (안전한 후퇴)**
벨트·탑승을 읽을 수 없는 차량에서는 "이 차량은 일부 정보를 읽을 수 없어 직접 확인해 주세요"만 표시하고 준비 완료를 말하지 않는다.

**시나리오 C — 겨울 아침 출발 (보조)**
"출발 준비" → 서리 제거 단계를 안내하고, 차량 제어가 열린 환경에서는 동의 후 실행·결과 확인.

**시나리오 D — 주행 시작 (정차 전용)**
기어를 D로 바꾸는 순간 모든 안내·제어를 멈추고 "정차 후 이용하세요"만 표시한다.

## 5. 개발 계획

### 5-1. 개발 환경과 구조
- Android(Kotlin, Jetpack Compose), minSdk 28, Pleos Connect Emulator(API 34)로 검증 `[진행 예정]`. Pleos Maven의 Vehicle 2.3.2 AAR을 내려받아 메서드·퍼미션을 직접 확인하고 연결 코드를 작성함(pleos 빌드, lint 통과)
- `core`(순수 Kotlin: 상태 머신·판정 로직·구역 대조) / `app`(UI·차량 어댑터) 분리. SDK·에뮬레이터 없이 전 시나리오를 재현하는 **Fake 차량 빌드**와 데모 패널 포함
- **자동 테스트 47개**(픽업 수용 기준 AC5.1~5.6 포함)가 통과한 상태. 폴링 없이 콜백/Flow 구독, 네트워크·계정·서버 없음

### 5-2. SDK/API 사용 내역 (Vehicle 2.3.2 AAR의 `javap`·Android lint로 확인한 시그니처, 에뮬레이터 동작 검증 `[진행 예정]`)
| 기능 | SDK / API | 퍼미션 | 상태 |
|---|---|---|---|
| 좌석별 탑승 | `Seat.getCurrentSeatOccupancy`, `registerSeatOccupancy`, `checkSeatOccupancyCapabilities` | CAR_SEATS | 연결 코드 작성 |
| 좌석별 안전벨트 | `Seat.getCurrentSeatBeltBuckledState`, `registerSeatBeltBuckledState`, `checkSeatBeltBuckledCapabilities` | CAR_SEATS | 연결 코드 작성 |
| 좌석 구분 | `SeatArea(SeatValue)`: ROW_1~3 × LEFT/CENTER/RIGHT → 뒷줄 좌·중·우 개별 조회 | - | 연결 코드 작성 |
| 도어·창문 열림 | `Door.getCurrentDoorPosition`/`registerDoorPosition`, `Window.getCurrentWindowPosition`/`registerWindowPosition`, `check…PositionCapabilities` | CAR_DOORS, CAR_WINDOWS | 연결 코드 작성. 위치값(Int)의 "닫힘" 기준은 지원 범위 최솟값으로 가정 → 에뮬레이터 검증 필요 |

**핵심 기능(픽업 모드·마무리 점검)은 모두 "조회" 계열 Vehicle State API만 사용**하므로, 제어·위치·TTS SDK가 열리지 않은 현재 상태에서도 동작하도록 설계했다. 주행 제한(CarUxRestrictions) 연동은 접근 경로 확인 후 추가 `[진행 예정]`이며, 현재는 기어 조건으로 차단한다.

### 5-4. 안전·개인정보·심사 대응
- **정차 전용:** DO 미선언, 기어가 P가 아니거나 읽지 못하면 즉시 차단(자동 테스트로 검증). 사용 퍼미션은 조회 계열 CAR_* 와 기어용 CAR_DRIVE이며, 제한적으로 개방될 수 있는 PRIVATE_* 계열은 쓰지 않는다.
- **아동 개인정보:** 아동의 이름·사진·나이 등을 **입력받지도 저장하지도 않는다.** 좌석 점유 여부(참/거짓)만 메모리에서 쓰고 즉시 버린다. 심사 가이드의 아동 개인정보 조항(보호자 사전 고지·동의)에 해당하는 수집이 없다.
- **위치:** 기기 안에서만 처리, 저장·전송·계정 없음. 로그에 좌표 미기록. 현재 연결에서는 위치 SDK가 신청 불가라 위치를 읽지 않는다. 위치 사용에 따른 이용약관·데이터 처리방침을 별도 작성 `[진행 예정]`
- **카테고리:** 보호자(운전자) 대상 앱이므로 "모빌리티 서비스"(Kids 카테고리 아님).
- 구역 데이터: 가상 샘플 5곳(데모용). 실제 단속 구역과의 일치를 주장하지 않고 "일 수 있어요"로 안내. 공공 데이터 연동은 확장 계획.

## 6. 기대효과 및 발전 가능성

### 6-1. 사용자 가치
- 급한 정차에서도 **좌석별로** 안전벨트·하차 방향을 확인해 아이 승하차의 실수를 줄인다.
- 안내는 "이상 있을 때만, 짧게". 뒤를 돌아보거나 폰을 볼 필요가 없다.
