# 02. 유즈케이스

액터: **운전자**, (선택) **동승자**, **시스템(앱)**, **차량(Pleos Vehicle Service)**

공통 전제
- 앱은 정차 전용. 기어 P가 아니거나 주행 제한(CarUxRestrictions)이 걸리면 화면 조작·제어를 중단한다.
- 음성은 TTS 온디바이스. 화면 문구는 한 줄 요약 + 필요한 항목 목록.

## UC1. 주정차 금지 구역 경고 (F1)
**트리거**: 기어가 D/R 등에서 P로 바뀜
**사전조건**: 위치 사용 가능, 구역 데이터 로드됨

| 단계 | 동작 |
|---|---|
| 1 | 앱이 기어 P 전환을 감지 |
| 2 | 현재 위치(FusedLocation)를 구역 데이터와 대조 (반경·폴리곤) |
| 3-a | 구역 안 → "여기는 주정차 금지 구역일 수 있어요" 음성 + 화면 경고, 구역 종류와 시간대 표시 |
| 3-b | 구역 밖 → 무음, 하차 점검(UC2)으로 이동 |
| 4 | 운전자가 "알겠어요"로 닫거나 "근처 다른 곳 찾기"(v2, 범위 밖) |

**수용 기준**
- AC1.1 구역 안에서 P 전환 시 3초 안에 경고가 뜬다.
- AC1.2 구역 밖이면 경고가 없다.
- AC1.3 위치를 못 얻으면 "위치를 확인하지 못했어요"를 한 번만 안내하고 UC2로 진행한다.
- AC1.4 경고 문구에 "일 수 있어요"처럼 **확정 표현을 피한다**(데이터 한계).

## UC2. 하차 전 점검 (F2)
**트리거**: 기어 P 유지 중 운전석 도어가 열리려 하거나, 운전자가 "내릴게요"를 누름 (구현 가능한 트리거를 docs/03에서 확정)

| 단계 | 동작 |
|---|---|
| 1 | 창문(전 좌석), 도어, 경고 정보, 뒷좌석 탑승 상태를 수집 |
| 2 | 이상 항목만 추려 요약: 예) "조수석 창문이 열려 있어요", "뒷좌석에 탑승자가 있어요" |
| 3 | 이상 없음이면 "모두 정상이에요"로 짧게 종료 |
| 4 | 이상 항목이 있으면 화면에 체크리스트, 항목별 "확인했어요" |

**수용 기준**
- AC2.1 이상 항목이 없으면 안내는 한 문장 이내.
- AC2.2 열린 창문이 있으면 몇 번째 좌석인지 구분해서 말한다.
- AC2.3 API로 읽지 못한 항목은 "확인 불가"로 표시하고 정상으로 간주하지 않는다.
- AC2.4 점검은 3초 이내에 완료되거나 타임아웃 후 부분 결과를 보여 준다.

## UC3. 뒷좌석 안내 (F3)
**트리거**: UC2 중 뒷좌석 탑승 감지

| 단계 | 동작 |
|---|---|
| 1 | "뒷좌석에 탑승자가 있어요. 함께 내렸는지 확인하세요" 음성·화면 |
| 2 | 동승자용 화면(큰 글씨): "내릴 때 주변 차와 자전거를 살펴보세요" 같은 짧은 안내 |
| 3 | 운전자가 "모두 내렸어요"를 누르면 항목 완료 |

**수용 기준**
- AC3.1 탑승 감지 시에만 표시한다(감지 불가 시 일반 문구 "뒷좌석을 확인하세요").
- AC3.2 뒷좌석 전용 오디오를 약속하지 않는다(화면·공용 음성만).

## UC4. 출발 전 시야 루틴 (F4)
**트리거**: 운전자가 "출발 준비"를 누름 (기어는 P)
**사전조건**: 제어 퍼미션 승인됨(미승인이면 안내 모드)

| 단계 | 동작 |
|---|---|
| 1 | 현재 상태 읽기: 외기 온도(가능하면), 앞유리 제습 상태, 와이퍼, 사이드미러·핸들 열선 |
| 2 | 루틴 제안: "서리 제거 시작할까요?" (제습 + 와이퍼 1회 + 사이드미러 열선 + 핸들 열선) |
| 3 | 운전자 동의 → 순서대로 제어 실행 |
| 4 | 각 항목이 **콜백으로 켜졌는지 확인**하고 결과를 체크 표시로 보고 |
| 5 | 실패 항목이 있으면 이유와 수동 방법을 안내 |
| 6 | 끝나면 "시야가 확보되면 출발하세요" |

**수용 기준**
- AC4.1 동의 없이 제어하지 않는다.
- AC4.2 제어 후 상태 확인에 실패한 항목을 성공으로 표시하지 않는다.
- AC4.3 기어가 P를 벗어나면 즉시 중단하고 변경한 설정을 임의로 되돌리지 않는다(사용자에게 알림).
- AC4.4 지원하지 않는 항목은 `checkXXXCapabilities` 결과로 건너뛰고 이유를 보여 준다.

## UC5. 설정·예외
| 시나리오 | 동작 |
|---|---|
| 음성 끄기 | 설정에서 음성 안내 on/off |
| 점검 항목 선택 | 창문, 도어, 뒷좌석, 시야 루틴을 개별 on/off |
| 주행 시작 | 진행 중인 모든 안내·제어 중단, 화면은 "정차 후 이용하세요" |
| 권한·API 불가 | 기능별로 "안내 모드"로 degrade하고 개발자 패널에 원인 기록 |

## 데모 시나리오 (심사용 3분)
1. (Fake/에뮬레이터) 도심 구역 좌표에서 기어 P → 경고 (UC1)
2. 하차 점검 → 조수석 창문 열림 + 뒷좌석 탑승 → 체크리스트 (UC2, UC3)
3. 겨울 아침 가정: "출발 준비" → 서리 루틴 실행·확인 (UC4)
4. 주행 시작 → 화면 차단 확인 (정차 전용)

## UC6. 등·하원 픽업 모드 (메인 기능, docs/08)
**트리거**: 운전자가 홈에서 "픽업 모드"를 켬 (기어 P, 설정에서 끌 수 있음)
| 단계 | 동작 |
|---|---|
| 1 | 뒷줄 좌석(왼쪽·가운데·오른쪽)의 탑승·안전벨트를 **좌석별**로 표시 |
| 2 | 벨트 미착용 좌석이 있으면 "뒷좌석 오른쪽 안전벨트를 확인하세요", 전원 확인 시 "안전벨트를 모두 확인했어요" |
| 3 | 뒷문이 열리면 정차 방향 설정에 따라 "오른쪽 문으로 내리세요" / 반대쪽 문이면 "차도 쪽 문이에요. 오른쪽 문으로 내려 주세요" |
| 4 | "모두 내렸어요" → 기존 하차 점검(남은 탑승자·창문·도어)으로 마무리 |

**수용 기준** (테스트: `PickupTest.kt`)
- AC5.1 픽업 모드를 켜기 전·설정에서 끈 경우 벨트·도어 안내를 하지 않는다.
- AC5.2 뒷줄 좌석을 개별 판단하고, 읽지 못한 값은 "확인 불가"이며 착용으로 간주하지 않는다.
- AC5.3 탑승자 전원 착용이 확인되기 전에는 "모두 확인했어요"를 말하지 않는다.
- AC5.4 기어가 P를 벗어나면 즉시 종료·차단하고 이후 신호로 되살아나지 않는다.
- AC5.5 아동 정보를 입력받지 않고 좌석 점유 불리언만 메모리에서 쓴다(저장·전송 없음).
- AC5.6 벨트·탑승 감지를 지원하지 않는 차량은 일반 문구("뒷좌석 안전벨트를 확인하세요")로 degrade하고 준비 완료를 말하지 않는다.
- 정차 방향(오른쪽/왼쪽)은 설정에서 바꾸며 안내 문구와 차도 쪽 문 경고에 반영된다. 같은 안내는 반복해서 말하지 않는다.
